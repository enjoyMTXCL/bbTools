## 修复 pnpm supply-chain 校验失败（xlsx 缺 integrity）

- 现象：pnpm 11.4+ 安全策略拒绝 `xlsx@https://cdn.sheetjs.com/xlsx-0.20.2/xlsx-0.20.2.tgz`（node-xlsx 的 tarball 依赖）缺 integrity 字段，报 ERR_PNPM_MISSING_TARBALL_INTEGRITY；`pnpm install --fix-lockfile` 未生效。
- 解法：curl 下载 tarball → node crypto 算 sha512 base64 → 手动编辑 pnpm-lock.yaml 的 resolution 加 `integrity: sha512-+nKZ39+...==`。用 `pnpm install --lockfile-only` 验证 supply-chain 校验通过。
- 沙箱限制记录：pnpm 在本环境跑 install 会被 safe-delete shim 拦截（trash `_tmp_xxx` 失败）；绕过沙箱后 store 的 sqlite 又只读（ERR_SQLITE_ERROR readonly）。结论：pnpm install 只能在用户终端跑。
- 补充：node 读取 Git Bash /tmp 路径会解析为 C:\tmp 报 ENOENT，临时文件要放项目目录内用 Windows 绝对路径。

## 修复 pnpm blockExoticSubdeps 拦截（xlsx URL 传递依赖）

- 现象：supply-chain 校验通过后，又报 ERR_PNPM_EXOTIC_SUBDEP——xlsx 是 node-xlsx 的**传递依赖**且走 sheetjs CDN URL，pnpm 11 默认 `blockExoticSubdeps: true` 只允许直接依赖用 URL/git 源。
- 解法：**`pnpm-workspace.yaml` 设 `blockExoticSubdeps: false`**（pnpm 11.22 实测不读 .npmrc 的 `block-exotic-subdeps`，`pnpm config get` 返回 undefined；该策略项只认 pnpm-workspace.yaml）。该策略无按包白名单，只能项目级关闭；xlsx 0.20.x 仅 sheetjs 官方 CDN 发布，来源可信，已注释说明。
- 环境结论：本机 pnpm 11.22 默认开启 minimumReleaseAge(1440min)/blockExoticSubdeps 两项供应链策略，旧项目易踩坑；均可在 .npmrc / pnpm-workspace.yaml 关闭。

## 修复：未修改却提示保存（isModify 误触发）

- 现象：数据文件化改造后，页面无任何修改直接跳转仍弹"是否保存"。
- 根因：onMounted 里 `loadData().then()` 的 `groupList.value = JSON.parse(d)` 赋值发生在 `watch(groupList, {deep:true})` 注册**之后**，加载赋值被 deep watch 误判为用户修改 → isModify=true。
- 修复：把 watch 注册移入 `loadData().then()` 内部（数据赋值完成后），初始赋值不再触发修改标记。注意：不能简单在 then 里先置 isModify=false，因为 deep watch 回调（flush:pre）在 then 同步段之后才执行，会把 false 又覆盖回 true，必须用"先注册监听"的时序解法。vue-tsc 通过。
